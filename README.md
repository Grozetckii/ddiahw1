# DDIA HW-1: Мониторинг микросервисов (Spring Boot + Prometheus + Grafana + K6)

## 🚀 Как запустить

Для запуска всего стека достаточно выполнить две команды в корне проекта:

```bash
cp .env.example .env
docker compose up --build -d
```

**Что произойдет:**
1. Соберутся и запустятся два экземпляра приложения (`app-1` и `app-2`).
2. Поднимется Prometheus и Grafana.
3. Контейнер `dashboard-generator` заберет список ручек из `/handlers` и сгенерирует дашборд.
4. Контейнер `k6` запустит фоновую нагрузку.

После запуска откройте Grafana:
* **URL:** `http://localhost:3000`
* **Логин:** `admin`
* **Пароль:** указан в вашем файле `.env` (`GRAFANA_PASSWORD`).

В разделе **Dashboards** появится готовый дашборд `Auto-generated Dashboard DDIA-HW-1`.

## 📊 Метрики и лейблы

Для сбора «золотых сигналов» используется стандартная метрика Spring Boot Actuator (Micrometer): `http_server_requests_seconds` (и её производные `_count`, `_sum`, `_bucket`).

### Лейблы
К стандартным лейблам Micrometer (`uri`, `method`, `status`) добавлены кастомные теги, проброшенные через переменные окружения:
* **`pod_id`** — идентификатор пода (env: `POD_ID`).
* **`datacenter`** — датацентр (env: `DATACENTER`).

Это позволяет фильтровать графики в Grafana по конкретному поду или датацентру, а также агрегировать данные по обоим экземплярам одновременно (выбор `All`).

### Для Latency выбрал тип `Histogram`
Он подходит, потому что раскладывает количество запросов по buckets с каждого пода.
При агрегации мы можем просуммировать buckets с одинаковыми значениями (лейбл le) и после этого корректно рассчитать перцентили.
В результате мы увидим правильную картину, агрегированную по всем подам.
